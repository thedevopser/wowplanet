# WowPlanet

Web application for tracking **World of Warcraft** progress: character profiles, collections
(mounts, pets, transmog…), Mythic+, raids, account-wide score.

**Stack**: Laravel 12 + Vue 3 through Inertia · FrankenPHP · PostgreSQL 18 · Redis 8 · data from the **Blizzard API**.

> The application runs in Docker, the tooling runs on your machine: tests, linting, static
> analysis and asset builds all use the local PHP and Node.

---

## 1. Machine requirements

To run the project in development you need, on your own machine:

| Tool | Purpose |
| --- | --- |
| **Docker** + **Docker Compose** | Runs app, worker, Vite, PostgreSQL and Redis. |
| **PHP 8.4** + **Composer** | PHP tooling: Pest, Pint, Larastan, Rector, Artisan. The `pdo_pgsql` and `redis` extensions are required — the local tooling talks to the stack directly. |
| **Node 26** + **npm** | JS tooling: Vitest, asset builds. |
| **Traefik** (local reverse proxy) | Serves the project over HTTPS at `wowplanet.dev.local`. It is a shared proxy, **not part of this repository** — it must already be running on the `dev-network` Docker network. |

> PHP coverage is the only tooling command that still runs inside the container: it needs **pcov**,
> which ships in the dev image and is absent from the local PHP.

`compose.yml` attaches to an **external** Docker network named `dev-network` and publishes its
routes through Traefik labels. Two prerequisites follow:

```bash
# Create the shared network (once, if it does not exist yet)
docker network create dev-network

# Resolve the local domain → add this line to /etc/hosts
127.0.0.1  wowplanet.dev.local
```

**PostgreSQL and Redis come with `compose.yml`**, there is nothing to install on your machine.
PostgreSQL 18 holds the data, Redis 8 holds the cache, the queue and the sessions, on three
separate database indexes — 1, 2 and 3. That split is not cosmetic: `cache:clear` issues a
`FLUSHDB`, so a shared index would wipe pending imports and sign everyone out on every cache flush.

> **One `.env`, two points of view.** The `DB_*` and `REDIS_*` variables are written from the
> machine's point of view — `127.0.0.1:55432` for PostgreSQL, `127.0.0.1:56379` for Redis — so that
> the local tooling can reach the stack. Inside the containers, `compose.yml` injects
> `DB_HOST=wowplanet-postgres` and `REDIS_HOST=wowplanet-redis`, which take precedence. This is the
> first trap in the project: both sets of values are correct, each in its own place.

## 2. Installation (first time, after cloning)

```bash
# 1. Copy the environment file
cp .env.example .env

# 2. Start the stack: app, worker, PostgreSQL and Redis (on dev-network)
make up

# 3. Install PHP and JS dependencies (local Composer and npm)
make install

# 4. Generate the application key
php artisan key:generate

# 5. Create the schema
php artisan migrate

# 6. (optional) Install the pre-commit quality hook
make install-hooks
```

> The application database `wowplanet` and the test database `wowplanet_test` are created the first
> time the PostgreSQL container starts. Initialisation scripts only run on an empty volume, so on a
> volume that already holds a cluster the test database has to be created by hand:
>
> ```bash
> docker compose exec postgres \
>     psql -U wowplanet -d postgres -c 'CREATE DATABASE wowplanet_test OWNER wowplanet'
> ```

Check that everything answers:

```bash
make psql       # SQL shell on the application database
make redis-cli  # Redis shell
make test       # the Pest suite, against wowplanet_test
```

## 3. What you need to fill in `.env`

| Variable | Required | Details |
| --- | --- | --- |
| `APP_KEY` | yes | Generated by `php artisan key:generate` (step 4). |
| `BLIZZARD_CLIENT_ID` | yes | OAuth client from the [Blizzard API](https://develop.battle.net/access/clients). |
| `BLIZZARD_CLIENT_SECRET` | yes | Secret of the Blizzard OAuth client. |
| `BLIZZARD_REGION` | yes | API region (`eu` by default). |
| `BLIZZARD_REDIRECT_URI` | yes | OAuth callback URL. In development: `https://wowplanet.dev.local/auth/blizzard/callback` (already in `.env.example`). |
| `ADMIN_BNET_ID` | yes (for the admin panel) | Your Battle.net ID, required to reach the administration panel. |
| `DISCORD_WEBHOOK_URL_CHANGELOG` | no | Discord webhook for the changelog. |
| `DISCORD_WEBHOOK_URL_DISCUSSION` | no | Discord webhook for discussions. |

> Blizzard credentials come from creating a client on the
> [Blizzard Developer Portal](https://develop.battle.net/). They are needed both for importing data
> and for Battle.net authentication.

## 4. Running in development

```bash
make dev       # Vite dev server (HMR) through Traefik
make worker    # "imports" queue worker (Blizzard imports, cross-character computations)
```

Access: **https://wowplanet.dev.local**

Stopping:

```bash
make dev-stop      # Stops Vite
make worker-stop   # Stops the worker
make down          # Stops the application
```

> **Worker**: FrankenPHP keeps the code in memory. After changing a job or an Artisan command,
> restart the worker for the change to be picked up: `docker compose restart worker`.

## 5. Everyday commands

| Command | Description | Runs |
| --- | --- | --- |
| `make test` | PHP tests (Pest), against `wowplanet_test`. | local, **stack required** |
| `make test-js` | JS tests (Vitest). | local |
| `make lint` | Fixes code style (Laravel Pint). | local |
| `make static` | Static analysis (Larastan). | local |
| `make refactor` | Automated refactoring (Rector). | local |
| `make quality` | lint + static + refactor + PHP and JS tests. | local, **stack required** |
| `make coverage` | PHP + JS coverage, HTML reports. | PHP in the container, JS locally |
| `make psql`, `make redis-cli` | SQL and Redis shells. | container |
| `make clean` | Clears the Laravel caches. | container |

Code style, static analysis and JS tests run without starting anything. Everything that executes
the Pest suite needs PostgreSQL: `make test` checks for it and says so in one line when the database
does not answer, rather than letting a stack trace unroll. PHP coverage needs the stack for a
different reason — it relies on pcov, which only exists in the container.

`make help` lists every available target.

## 6. Architecture at a glance

- **Backend** — Clean Architecture (`Domain` → `Application` → `Infrastructure` / `Http`),
  Laravel 12, served by FrankenPHP.
- **Frontend** — Vue 3 with Inertia and Pinia, optional server-side rendering through the
  `inertia-ssr` sidecar. Controllers render the pages under `resources/js/pages/`, and the
  `api.php` routes serve XHR calls.
- **Persistence** — PostgreSQL 18 for the data, Redis 8 for cache, queue and sessions, each on its
  own database index. Databases are collated as `fr-FR` through the ICU provider, which gives
  accented names French sort order.

Architecture details and conventions live in the [`documentation/`](documentation/) directory,
also served at `/docs` in a local environment. Those pages are in French only.
